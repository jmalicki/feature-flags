# Source code and personal data in development environments

Research for PR #7. This pass adds incident records, operating practices, and objections to the existing access, data, and agent ledger. The central distinction is between where files live, who can read them, where they can go, and what evidence survives if they leave. A report of code or data present on a system does not establish that every record was taken. A control announcement does not establish deployment or effectiveness.

## What the essay can say

- **Remote development changes where some controls can be enforced.** Keeping a working tree on a managed host reduces the copies on client devices. Repository access, workspace permissions, browser and editor transfer rules, and service credentials determine who else can get a copy. The enterprise repository and build pipeline remain security boundaries in their own right.
- **A development environment can hold production-sensitive material even when it uses separate infrastructure.** Check what arrives through database refreshes, support evidence, debugging logs, screenshots, test integrations, and credentials. A named owner, verified contents and a retention limit are more informative than the label “test.”
- **A protected environment can still support realistic testing.** Generated fixtures work for many cases. A workload may need certain consistent identifiers, data shapes or volumes. ING describes the work required to get synthetic payment messages accepted. GitLab describes a different choice for migration benchmarks, with a restricted, expiring clone and a smaller set of outputs visible in ordinary review.
- **Plan for prevention and investigation.** Some controls block an action. Others record an event or reveal a pattern after the fact. Policy, retention, analyst staffing, and a usable approved path for legitimate work belong in the design.
- **Give agents a smaller set of actions than people performing the full job.** Spotify describes a background agent that works on code while a surrounding service handles publication. A development box alone gives no assurance about what the agent can publish, reach, or read.

## Code loss and authorized access

| Case and evidence | Measure or observation | Bearing on the essay |
| --- | --- | --- |
| Goldman Sachs, 2009 incident, New York Court of Appeals opinion in 2018 | Staff working away from the office were authorized to use remote login to their Goldman desktops, keeping files inside the firm. A developer with broad source access copied trading code from a work computer. Security staff found the transfer after the fact and recovered relevant history from a network snapshot. [Court opinion, facts at 386–390](https://www.nycourts.gov/Reporter/3dseries/2018/2018_03174.htm) | A directly relevant finance example of remote access from home coexisting with a work-computer disclosure. The network copy of the logs aided reconstruction. The opinion does not measure the effectiveness of remote access controls in general. |
| Qualcomm, 2002 conduct, 2007 sentencing release | While still employed, an engineer obtained access to a protected repository without a work reason and took trade secrets. He later admitted the conduct. [DOJ sentencing release](https://www.justice.gov/archive/criminal/cybercrime/press-releases/2007/laudeSent.pdf) | An approval gate relies on evidence of business need, how much access is granted, and when it expires. The release does not describe the subsequent engineering controls. |
| Okta, December 2022, company statement | GitHub alerted Okta to suspicious access. Okta confirmed copies of Workforce Identity Cloud repositories. It restricted repository access, suspended third-party GitHub integrations, checked access and commit integrity, and rotated GitHub credentials. Okta reported no unauthorized customer-data or service access. [Okta incident notice](https://sec.okta.com/articles/2022/12/okta-code-repositories/) | A repository can be the point of loss even if the workstation estate is managed. A source confidentiality incident and a production integrity investigation may need different evidence. |
| LastPass, 2022 incidents, company report and subsequent ICO findings | LastPass reported access to source repositories and secrets in the development environment and then rebuilt the environment and hardened controls. The ICO found that material in development included credentials with production reach. A later, connected incident exposed customer backups. [Company incident report](https://blog.lastpass.com/posts/security-incident-update-recommended-actions) · [ICO penalty notice, ¶¶42–45](https://ico.org.uk/media2/xfbl1uaa/lastpass-uk-ltd-penalty-notice.pdf#page=16) | Separate names and machines did not enforce separate authority. The useful control is distinct credentials and reach across environments. |
| F5, October 2025 disclosure | F5 reported the theft of portions of BIG-IP source and vulnerability information from engineering systems. It reported that independent reviews found no evidence of tampering with build or release pipelines. F5 later described engineering knowledge artifacts that also held customer interactions and troubleshooting information. [SEC filing, item 1.05](https://www.sec.gov/Archives/edgar/data/1048695/000104869525000149/ffiv-20251015.htm) · [F5 follow-up](https://www.f5.com/company/blog/lessons-we-are-learning-from-our-security-incident) | Code, build integrity, and engineering support notes need separate handling. The company describes what its investigation found, without giving a general measure of containment. |
| 1Password, November 2026, preliminary company report | A compromised corporate GitHub account was involved in copying private repositories and gaining access to CI/CD and backend systems. Some customer account information was copied. The company says vault contents and their keys remained inaccessible. It restored clean service versions, revoked unwarranted access and began rotating affected credentials. [Company update, November 25](https://1password.com/blog/update-on-nov-2026-security-incident) | The copied source, lost account information, and protected vault data had different boundaries. The company describes an ongoing investigation. The checkout topology is unpublished. |
| Société Générale, 2009 conduct, jury verdict announced in 2010 | The case describes role-based limits on trading code, rules on removable copies, and monitoring. An employee took code he could read for his job. Records helped investigators substantiate the theft. [DOJ verdict release, pp. 1–2](https://www.justice.gov/sites/default/files/criminal-ccips/legacy/2012/03/15/agrawalVerdict.pdf) | An authorized reader can still disclose what they can see. Evidence of misconduct and prevention are distinct outcomes. |
| Heroku, 2022 incident, company review | A credential associated with an archived repository was involved in an incident that reached customer repositories through Heroku's GitHub integration. Heroku revoked tokens, stopped issuing new ones, reduced permissions and tightened database access. [Heroku incident review](https://www.heroku.com/blog/april-2022-incident-review/) | Dormant code and third-party integration credentials belong in scope. The checkout host is only one boundary. |
| Toyota T-Connect, October 2022 disclosure | A subcontractor inadvertently left source accessible in a public repository. Toyota identified about 296,000 email addresses and customer IDs as potentially exposed, made the source private, and rotated the relevant key. Its records could neither establish nor rule out third-party access to customer data. [Toyota disclosure, §§1–2, Japanese](https://global.toyota/jp/newsroom/corporate/38095972.html) | Confirmed public source and possible personal-data exposure are separate claims. |
| CrowdSec, May 2026 incident, September postmortem | A compromised departed developer's account retained repository access for handover after infrastructure access ended. The company reports about 170 private repositories copied, delayed discovery and insufficient routine Git history for its investigation. It revoked access, received historical activity from GitHub, rotated credentials and extended endpoint monitoring. [CrowdSec postmortem](https://www.crowdsec.net/blog/tanstack-supply-chain-attack-analysis) | A handover exception has an exposure window. CrowdSec attributes the theft to account compromise. |
| Sophos, October 2026 root-cause report | A compromised employee device passed compliance even though its endpoint agent had stopped reporting. A third-party authorization remained usable after sessions were revoked and the password reset. Sophos separately removed that access and added live agent reporting to device compliance. [RCA, Impact and Resolution](https://www.sophos.com/en-us/trust/root-cause-analyses/inc-2026-002) | Revocation needs to include delegated authorization. The source reports unauthorized read requests rather than a count of copied repositories. |

## Personal data in test, analytics, and support

| Case and evidence | Measure or observation | Bearing on the essay |
| --- | --- | --- |
| Stylez, 2021 Singapore PDPC decision | The regulator found that data on 9,983 individuals was taken from a separate testing database created in 2016 from portal data. Production and backup databases were unaffected. The test copy was retained for an extended period. [PDPC decision, ¶¶2–4 and findings](https://www.pdpc.gov.sg/-/media/Files/PDPC/PDF-Files/Commissions-Decisions/Decision---Stylez-Pte-Ltd---04082021.pdf) | Separation limits how far a breach can reach. It cannot reduce the sensitivity of records already copied into the test environment. |
| Toronto District School Board, 2024 incident, 2025 Ontario IPC case note | A test lab held real data on about 280,000 students and staff. A subset of operational data was taken and posted externally. The board committed to removing production data, using anonymization, adding MFA, and segmenting test and production. [Ontario IPC, Background and Findings](https://www.ipc.on.ca/en/cases-of-note/just-because-its-test-environment-doesnt-mean-privacy-risks-arent-real) | Keep the size of the dataset separate from the number confirmed taken. This combines content minimization, authentication and network separation in one response. |
| Singapore Land Authority, August 2026 ministerial answer | Unauthorized access affected a vendor-managed cloud development and systems integration testing dataset. Live systems were unaffected. The dataset was intended to contain only mock and anonymized data. The agency later found that real personal information was still present. [Ministry of Law, oral answer ¶¶1–3](https://www.mlaw.gov.sg/oral-answer-by-senior-minister-of-state-for-law-mr-murali-pillai-on-the-singapore-land-authority-data-security-incident/) | Check what a test dataset contains and keep an owner for refreshed copies. The answer describes an active investigation. |
| Rakuten Securities, November 2026 disclosures | The company located the incident in a test environment. The November 24 update reports personal information compromised in about 4.41 million records, potentially including duplicates, and separately reports code or ID-only data associated with about 11.98 million accounts. [November 17 notice](https://www.rakuten-sec.co.jp/web/company/newsrelease/pdf/press2026111702.pdf) · [November 24 follow-up](https://www.rakuten-sec.co.jp/web/company/newsrelease/pdf/press2026112402.pdf) | The units are records and accounts. The figures should not be added as unique people. |
| I’LL Inc., November 2026 notice | The company disclosed acquisition of data in verification and integration-test systems, mostly demonstration data but including some real customer-related data and external integration credentials. It took affected systems offline, isolated networks and began credential rotation. It announced prohibitions on real data and production credentials in the affected class of environment. [Company notice, §§1–3, Japanese](https://www.ill.co.jp/info/261122/) | A mostly synthetic or demo environment can contain exceptions. The notice distinguishes action already taken from announced policies. |
| Desjardins, 2017–2019 breach, Canadian privacy commissioner findings | Copies on shared drives escaped restrictions on data in the original warehouse. The findings cover close to 9.7 million people whose data was accessed or taken. The firm restricted shared directories, tightened approvals, and deployed a controlled analysis environment with limits on handling and extraction. [OPC findings, ¶¶75–82 and 114–118](https://www.priv.gc.ca/en/opc-actions-and-decisions/investigations/investigations-into-businesses/2020/pipeda-2020-005) | An analytics rather than coding example. Downstream copies and exports need governance even when the original data store has access controls. |
| Morgan Stanley, 2011–2014 conduct, 2016 SEC order | Internal portals lacked effective business-need authorization for certain reports. The SEC describes shortcomings in testing authorization and reviewing access activity, alongside endpoint controls. Morgan Stanley settled without admitting or denying the findings. [SEC order, ¶¶6–15](https://www.sec.gov/files/litigation/admin/2016/34-78021.pdf) | A permitted report can be a disclosure path independent of source code and of where a developer edits it. |
| Block / Cash App Investing, December 2021 event, 2022 SEC filing | Block reported that a former employee downloaded brokerage reports after employment had ended. Access to the reports had been part of the former job. Block contacted approximately 8.2 million current and former customers. [SEC filing, Item 8.01](https://www.sec.gov/Archives/edgar/data/1512673/000119312522095215/d343042d8k.htm) | The number notified does not measure the number whose records were taken. The filing does not identify how access remained possible. It gives reason to test revocation across the systems that hold report copies. |
| PINC Interactive, 2022 Singapore PDPC decision | A staging dataset with 248,897 dummy records also held personal data on 3,916 real users. The regulator identified likely exposure routes involving copies on developers' own devices and a staging access-control gap. [PDPC decision, ¶¶2–5 and 9–12](https://www.pdpc.gov.sg/-/media/files/pdpc/pdf-files/commissions-decisions/decision---pinc-interactive-pte-ltd---04022022.pdf) | A mostly dummy dataset still needs controls for every real record. The source does not establish which exposure route was used. |
| Australian Red Cross Blood Service, 2016 incident | The privacy regulator found a public exposure of a vendor-managed UAT backup containing contact and sensitive eligibility information on about 550,000 prospective blood donors. The service changed supplier security requirements and reduced the eligibility information it collected. [OAIC report, “The data breach” and “Changes to information handling practices”](https://www.oaic.gov.au/privacy/privacy-assessments-and-decisions/privacy-decisions/Investigation-inquiry-reports/donateblood.com.au-data-breach-australian-red-cross-blood-service) | Backups and third-party handling can expand the exposure of a test copy even when live services are elsewhere. |
| Times Software, 2020 Singapore PDPC decision | Staff retained payroll data long after a 2015 feature was delivered. A written policy required deletion at sign-off, and the organization had no checks to verify compliance. [PDPC decision, ¶¶13–14](https://www.pdpc.gov.sg/-/media/Files/PDPC/PDF-Files/Commissions-Decisions/Decision---Times-and-Others---18062020.pdf) | An expiration date and verification of deletion address a different failure from authorization at creation. |
| Okta support diagnostics, October 2023 | Routine diagnostic artifacts contained session credentials. Investigators initially queried too narrow a set of download events, and log ingestion delay further complicated reconstruction. Okta revised the scope and changed support access and retention. [Root-cause report](https://sec.okta.com/articles/2023/11/unauthorized-access-oktas-support-case-management-system-root-cause/) · [Follow-up](https://sec.okta.com/articles/harfiles/) | Adjacent support plane. Scrub sensitive diagnostic artifacts before sharing and test that investigators can find relevant actions across event types. |

## Questions to press in editorial review

| Objection | What would answer it |
| --- | --- |
| “Our engineers need real cases to debug.” | Name the workload and the data properties needed. Separate synthetic input, masked or transformed datasets, and exceptional controlled use of real records. Run output and log review at the same boundary. NIST describes disclosure-risk evaluation and protected access methods alongside de-identification techniques. [NIST SP 800-188](https://csrc.nist.gov/pubs/sp/800/188/final) |
| “We can block transfers and get on with it.” | Explain which client and service paths enforce the control and which legitimate work needs an approved export. Document whether the policy covers file sync, IDE operations, code publishing, and support attachments. The iBusiness restrictions apply to its managed browser, while a separate network policy governs the hosted environment. |
| “If we can audit Git, we’ll know who took the code.” | State what repository events can prove, where they're retained, and what could corroborate the origin or later movement of a copy. Distinguish an alert, a confirmed policy violation, and a measured disclosure. |
| “How much will it cost to operate this?” | Give the operating owner, severity and triage criteria, review and retention access, and time to resolve false alarms. Symantec is evidence of substantial early workload. It supplies no general precision estimate. |
| “The agent works in the same place a person does, so it can use the same authority.” | Specify who approves publication and production access, and which identity and scope the tools actually enforce. Spotify's intermediary gives an example of a different publication boundary. |

The cited incidents establish failures and responses. The deployment reports establish particular controls in use or at pilot stage. This evidence does not estimate how many leaks a move off laptops prevents or how well a given tool detects a determined insider.
