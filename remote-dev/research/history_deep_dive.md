# Development away from the laptop, 2005–2015

Research memo for PR #7, based on the draft at `33328f1`. The use dates below take priority over publication dates. The search followed personal blogs and their links, editor and build problems, talk demonstrations and slides, bug reports, forums, and interviews. The examples establish when particular workflows were in use and who described them. The record is too uneven to estimate how common each setup was across employers.

## How to use this in PR #7

**Present the development server as an ordinary way to work.** Open with a developer editing, previewing, and testing on their assigned host. Facebook's 2012 testing talk shows all three on the same machine. Daniel Roseman's post about getting Vim to copy text to his Mac, and David Singleton's story about replacing a corrupted Last.fm VM, can carry details about what it felt like to use one. Give each example its date in a clause or citation.

A possible opening:

> At Facebook, your first day on the web codebase included setting up a development server. In a 2012 talk about engineering at Facebook, David Mortenson showed a Mac terminal editing PHP on his dev host, a browser loading his Facebook profile from the same machine, and a test run he started there. You had a machine where you could change the site, see the result, and run the tests before sending the change for review.

Cut the chronology in “How the industry got here” and its timeline figure. Use the space to show where the code lives, where the editor runs, and where the build and tests happen. Stripe's early synced copy and Google's distributed builds are useful comparisons because they put different parts of the work on different machines. The dates, the editor releases, and individual migrations can live in the notes. The essay can then get to its present-day question. What should a coding agent be able to reach on the machine engineers already use?

## Period tooling

The 2014 NetBeans 8.0 documentation describes three configurations already available to users. A local IDE could copy source to a remote host, use shared mounts, or edit source held on a remote host using SFTP while invoking builds and debugging there. Full remote mode cached source locally, which matters for claims about where copies are allowed. Use this as evidence of available tooling. The documentation leaves uptake open. [NetBeans documentation](https://apache.googlesource.com/netbeans-website/%2B/4a54f08accee248318a52f567d28b3d983cd649b/netbeans.apache.org/src/content/kb/docs/cnd/remote-modes.adoc)

## Limits on the rewrite

A reported daily practice, a team onboarding convention, a tool that made the practice possible, and a company adoption announcement answer different historical questions. Preserve those distinctions wherever the body uses a historical example. The record includes named teams using hosted systems and named teams doing day-to-day work locally, sometimes at the same employer. Treat the team and workload as the unit of comparison. The older entries include individual accounts and specialist workflows. The date a later account was published can document an earlier practice when the witness dates their use. None of these dates establishes an industry-wide first or an adoption rate.
